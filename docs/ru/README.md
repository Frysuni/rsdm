# Команды {#commands}

Используйте `rsdm --help` или добавьте `--help` к любой команде для точного синтаксиса установленной версии. Команды принимают `--config <path>` (по умолчанию `/etc/rsdm.toml`); путь также можно задать переменной окружения `RSDM_CONFIG`.

## Справочник команд {#command-reference}

| Команда | Назначение |
| --- | --- |
| `rsdm dm` | Запустить DM и его Greeter на настроенном VT (обычно через systemd) |
| `rsdm lock` | Заблокировать текущий сеанс Wayland |
| `rsdm idle` | Запустить мониторинг бездействия на основе данных композитора |
| `rsdm unlock [--user <name>]` | Аварийно разблокировать работающий RSDM Lock с авторизацией root |
| `rsdm status` | Показать настроенные возможности и текущее состояние блокировки |
| `rsdm validate-config` | Проверить административный файл TOML |
| `rsdm logs` | Прочитать записи журнала RSDM за текущую загрузку |
| `rsdm session start -- <command>` | Запустить сеанс под управлением координатора |
| `rsdm session attach` | Подключиться к существующему графическому сеансу |
| `rsdm session finalize [names...]` | Опубликовать окружение композитора и завершить подготовку |
| `rsdm session status` | Получить область управления, фазу, приложения и возможности |
| `rsdm session stop` | Подготовить приложения и запросить выход |
| `rsdm session cancel` | Запросить отмену перед демонтажем инфраструктуры сеанса |
| `rsdm app -- <command> [args...]` | Зарегистрировать и запустить приложение |
| `rsdm power reboot` | Подготовить сеанс и запросить перезагрузку |
| `rsdm power poweroff` | Подготовить сеанс и запросить выключение |

Режимы запуска, политики приложений и значения результатов описаны в [Session Manager](session-manager.md). Выполняйте команды session/app/lock/idle от имени пользователя рабочего стола. Системная служба запускает DM с привилегиями, необходимыми для PAM и управления VT.

## Распространённые задачи {#common-tasks}

```sh
rsdm --version
rsdm validate-config --config ./rsdm.toml
rsdm status
rsdm session status
rsdm logs --component dm --lines 50
rsdm logs --follow
```

### Журналы {#logs}

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `-n, --lines <N>` | `200` | Количество последних записей |
| `-f, --follow` | выкл. | Вывод новых записей до Ctrl+C |
| `--component <name>` | `all` | `all`, `dm`, `idle`, `lock` |

При фильтрации сохраняются права доступа к журналу. Для отдельного экземпляра DM используйте `journalctl -b -u rsdm@tty2.service` (замените имя экземпляра). Для пользовательского координатора и служб приложений — `journalctl --user -b`.

## Вывод CLI {#cli-output}

Терминальные отчёты используют панели, цвета статуса и обычную прокрутку. Перенаправленные потоки, непустой `NO_COLOR`, `TERM=dumb` и терминалы уже 28 колонок используют простой текст. Предупреждения и ошибки остаются в stderr.

```sh
env NO_COLOR=1 rsdm status
rsdm session status > session-status.txt
```

::: details Формат журнала и скрипты
Оформленный вывод декодирует записи журнала с отметками времени UTC, уровнями и источниками без пейджера. Простой вывод делегирует форматирование `short-precise` и обычное поведение пейджера/follow программе journalctl. Успешные запуски приложений, запросы finalize и cancel могут отображать подтверждение в оформленном выводе.

В автоматизации используйте коды выхода. Отмена или неудачный/неизвестный запрос сеанса возвращают ненулевой код. Успешный запрос может означать подготовку или нативное делегирование, а не завершившийся выход; см. [результаты сеанса](session-manager.md#status-and-outcomes).
:::
