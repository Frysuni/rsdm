# Блокировка при бездействии {#idle-locking}

Idle отслеживает бездействие по данным композитора и запускает блокировщик после настроенной задержки. Он работает независимо от DM.

## Включение {#enable}

::: code-group

```toml [TOML]
[lock]
enable = true

[idle]
enable = true
timeout = 300
```

```nix [NixOS]
services.rsdm.lock.enable = true;
services.rsdm.idle = {
  enable = true;
  timeout = 300;
};
```

:::

Модуль NixOS устанавливает пользовательскую службу графического сеанса. На других дистрибутивах включите поставляемую службу из графического сеанса:

```sh
systemctl --user daemon-reload
systemctl --user enable --now rsdm-idle.service
```

Для композитора без интеграции с `graphical-session.target` запускайте `rsdm idle` из его конфигурации автозапуска. Используйте один монитор бездействия. Остановите дублирующие автоматические блокировщики. Для диагностики в foreground вместо службы выполните `RUST_LOG=rsdm_idle=debug,rsdm_lock=debug rsdm idle`.

## Ингибиторы {#inhibitors}

По умолчанию учитываются ингибиторы бездействия приложений, например при воспроизведении видео. Установите `ignore_inhibitors = true` в `[idle]` для отслеживания физического отсутствия ввода. Требуется `ext-idle-notify-v1` версии 2; при версии 1 ингибиторы продолжают учитываться.

Перед блокировкой все seats должны перейти в состояние бездействия. Активность сбрасывает таймер, но никогда не разблокирует экран. При ошибке блокировщик запускается повторно, пока все отслеживаемые seats остаются неактивными.

## Команды при блокировке и разблокировке {#run-commands-when-locking-or-unlocking}

```toml
[idle]
enable = true
timeout = 300
on_lock = [["notify-send", "Screen locked"]]
on_unlock = [["notify-send", "Screen unlocked"]]
```

Пример требует `[lock].enable = true`. Хуки выполняются от имени пользователя рабочего стола, по порядку, как буквальные массивы argv. Используйте явный `sh -c`, только если намеренно требуется синтаксис оболочки.

::: details Время выполнения хуков
Встроенный блокировщик сообщает о подтверждённой композитором блокировке по частному каналу готовности. `on_lock` выполняется после этого подтверждения. Для пользовательского foreground-блокировщика готовность означает запуск процесса. `on_unlock` выполняется только после успешного выхода вслед за готовностью (включая аварийную разблокировку). Он не запускается после сбоя, сигнала или ненулевого кода выхода. На каждую фазу хуков выделено 30 секунд; при истечении времени группы процессов хуков завершаются, а последующие хуки этой фазы пропускаются. Новый цикл блокировки может начаться до завершения предыдущих хуков. Под пользовательской службой управляемые блокировки имеют собственный transient scope, поэтому перезапуск монитора не убивает активную блокировку.
:::

## Другой блокировщик {#use-another-locker}

```toml
[idle]
enable = true
lock_command = ["swaylock"]
```

Используйте foreground-команду, работающую до разблокировки. Встроенный Lock может оставаться отключённым при настроенном пользовательском блокировщике.

::: warning Приостановка
Idle реагирует на бездействие по данным композитора. Сам по себе он не гарантирует блокировку экрана перед каждой приостановкой системы. Если требуется блокировка до сна, используйте поддерживаемую композитором/окружением интеграцию с подтверждением готовности и проверьте её отдельно.
:::

См. [настройку](configuration.md#idle) и [устранение неполадок](troubleshooting.md).
