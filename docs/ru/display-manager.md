# DM и Greeter {#dm-and-greeter}

DM управляет входом и выбранным виртуальным терминалом Linux. Greeter — его интерактивный терминальный интерфейс. После аутентификации PAM DM запускает выбранный сеанс Wayland и ожидает его завершения.

## Выбор сеанса {#select-a-session}

По умолчанию Greeter перечисляет установленные записи Wayland .desktop. Используйте фиксированный сеанс, чтобы пропустить выбор.

::: code-group

```toml [TOML]
[dm]
fixed_session = "niri-session"
```

```nix [NixOS]
services.rsdm.dm.fixedSession = "niri-session";
```

:::

Укажите ID desktop-записи (предпочтительно), уникальное имя/Exec или буквальную команду. Удалите параметр для восстановления обнаружения. Пути поиска и настройки TTY описаны в [конфигурации](configuration.md#dm-and-greeter).

## Управление {#controls}

| Клавиша | Действие |
| --- | --- |
| Tab / Down | Следующее поле |
| Shift+Tab / Up | Предыдущее поле |
| Left / Right | Изменить сеанс |
| F2 / Enter в поле сеанса | Открыть список сеансов |
| Enter | Перейти дальше или выполнить аутентификацию |
| F1 | Меню внешнего вида, если включено |
| F11 / F12 | Перезагрузка / выключение |
| Esc | Выход к консольному входу, если разрешён |

Действия питания и выход в консоль требуют повторного нажатия для подтверждения. Другая клавиша отменяет подтверждение и поглощается. PAM может запросить дополнительные данные, например одноразовый пароль.

## Внешний вид {#appearance}

```toml
[dm.design]
theme = "nord"
border_style = "modern"
background = "rain"
title_mode = "hostname"
```

F1 изменяет текущий экземпляр Greeter. Чтобы сохранить оформление между входами, измените системную конфигурацию. См. [все параметры оформления](configuration.md#appearance).

## Несколько мониторов {#multiple-monitors}

Виртуальный терминал Linux предоставляет одну общую сетку символов. Ядро может дублировать её на подключённые дисплеи; Greeter не может независимо выбирать монитор или отображать отдельные интерфейсы. Lock имеет настройки для каждого выхода, поскольку работает внутри Wayland.

::: details Выбор консольного выхода
Параметры дисплеев ядра (например, `video=HDMI-A-1:d`) могут влиять на разъёмы, активные при загрузке. Применяйте их через загрузчик или NixOS boot.kernelParams только при соответствии оборудованию и проверяйте, что композитор может восстановить нужный выход. Сохраняйте доступ к рабочей консоли.
:::

## Резервный консольный вход {#console-fallback}

Резервный вход включён по умолчанию, но ограничен политикой входа. Для передачи VT системному login требуются одновременно `deny_root = false` и `allowed_groups = []`. Аутентификация и ограничения попыток переходят к обычной политике консольного входа.

::: warning
Сохраните ограничительную политику по умолчанию, если полагаетесь на ограничения учётных записей RSDM. Для восстановления используйте отдельный VT.
:::

::: details Служба и время жизни сеанса
Запускайте DM через systemd unit с соответствующим `TTYPath`. `StandardInput=tty` и вывод в журнал отделяют вывод программы от Greeter. Поставляемый unit управляет runtime-масками getty/autovt. Избегайте `TTYReset`, `TTYVHangup` и `TTYVTDisallocate` при остановке службы: пользовательский сеанс может всё ещё владеть VT.

DM использует настроенную службу PAM, передаёт seat и TTY в logind, передаёт окружение PAM и запускает рабочий стол с учётными данными пользователя. Session Manager обычно оборачивает исходную команду Exec. PAM остаётся открытым до завершения фактического рабочего стола. См. [архитектуру](ARCHITECTURE.md).
:::

Для включения, отключения или переноса службы следуйте [руководству активации](installation/activate.md) или [руководству NixOS](installation/nixos.md).
