# Архитектура {#architecture}

RSDM использует общий терминальный интерфейс с отдельными бэкендами для Linux VT и Wayland. Аутентификация, жизненный цикл сеанса и отрисовка имеют разные зоны ответственности.

## Рабочее пространство {#workspace}

| Крейт | Назначение |
| --- | --- |
| rsdm-core | Доменные типы, порты, конфигурация и сценарии входа |
| rsdm-infra | PAM, обнаружение пользователей/сеансов, владение VT, хранилище и запуск DM |
| rsdm-system | Дескрипторы процессов Linux, часы, идентификаторы поколений и транспорт logind |
| rsdm-ui | Общее посимвольное оформление, палитры, анимация, заголовок и меню |
| rsdm-tui | Бэкенд Greeter на Ratatui и ввод |
| rsdm-lock | Поверхности session-lock Wayland, отрисовка консольного шрифта и аутентификация |
| rsdm-idle | Уведомления Wayland о бездействии, надзор за блокировщиком и хуки |
| rsdm-session-manager | Пользовательский жизненный цикл, units приложений, восстановление и XSMP |
| rsdm-cli | Маршрутизация публичных команд, диагностика и монитор питания |

Core не зависит от API Linux и библиотек отрисовки. UI зависит от Core. Session Manager зависит от Core и System без зависимости от PAM или интерфейсов.

## Жизненный цикл входа {#login-lifecycle}

1. DM проверяет конфигурацию, определяет сеансы и получает свой VT. Он отклоняет дублирующий экземпляр и ждёт существующих владельцев.
2. Greeter показывает форму входа. Вспомогательный процесс, владеющий PAM, аутентифицирует пользователя и применяет окончательную политику учётной записи.
3. Вспомогательный процесс создаёт сеанс logind с его seat, TTY и метаданными рабочего стола Wayland. PAM может разблокировать связку ключей пользователя.
4. Greeter очищает и освобождает VT после аутентификации. Владелец PAM запускает дочерний процесс с барьером запуска, новым образом rsdm и запечатанным запросом с проверенными настройками сеанса.
5. Дочерний процесс инициализирует группы, сбрасывает привилегии, применяет окружение, переходит в HOME и выполняет исходную команду через exec, обычно с обёрткой Session Manager.
6. Владелец PAM с правами root отслеживает фактическое время жизни сеанса, выполняет ограниченное по времени восстановление от UID рабочего стола и закрывает PAM. DM ждёт освобождения VT перед повторной отрисовкой.

::: details Границы процессов и терминала
Владелец PAM находится в scope сеанса logind. Перезапуск службы намеренно не завершает работающий рабочий стол. Проверки владения VT охватывают управляющие терминалы и открытые дескрипторы VT; нечитаемое состояние процесса считается занятым. Greeter временно подавляет консольные сообщения и восстанавливает сохранённую политику при выходе.

Барьер запуска позволяет владельцу PAM попытаться получить delay-ингибитор logind до настройки пользовательского сеанса; при ошибке родителя барьер закрывается. Ингибитор root удерживается до завершения пользовательской очистки и PAM. См. [питание и время жизни PAM](reference/session-lifecycle.md#power-and-pam-lifetime).
:::

## Отрисовка и Lock {#rendering-and-lock}

Оба интерфейса отрисовывают одинаковые оформленные символьные ячейки через общую UI Surface. Greeter адаптирует их к сетке символов VT; Lock растеризует их опубликованным консольным шрифтом и применяет масштабирование выхода. У каждого независимая конфигурация оформления.

Lock использует `ext-session-lock-v1`, создаёт непрозрачные поверхности и ждёт подтверждения композитора. Аутентификация работает отдельно от цикла событий Wayland. Аварийная разблокировка аутентифицируется, как описано в [безопасности](SECURITY.md#lock-screen). Персональное переопределение может сохранять только выбранные визуальные поля.

Idle отслеживает каждый seat через ext-idle-notify-v1. Готовность встроенного блокировщика передаётся по частному каналу от подтверждённой блокировки, внешний foreground-блокировщик сообщает о готовности при запуске процесса. Хуки выполняются от пользователя.

## Координация сеанса {#session-coordination}

Координатор на UID владеет одним поколением и незаменяемым именем службы D-Bus. Типизированные запросы поступают в последовательный актор жизненного цикла; рабочие задачи выполняют операции systemd, подготовку приложений, проверку готовности и восстановление.

Зарегистрированные запуски используют transient units пользователя. Координатор записывает владение до побочных эффектов и проверяет invocation, дескрипторы процессов и cgroups при действиях. Он сохраняет нативный жизненный цикл рабочего стола, где это возможно. Политики приложений, готовность и отмена доступны через [Session Manager](session-manager.md).

::: details Асинхронность и реализация восстановления
Команды CLI session, app и power владеют runtime Tokio. Владелец PAM запускает свой runtime ингибитора после fork. Lock продолжает цикл событий во время работы задач питания/аутентификации. XSMP использует отдельный поток libSM/libICE с ограниченным временем завершения. Leases и записи восстановления приватны, операции файловой системы отделены от ожидания D-Bus.

Слоты запросов, абсолютные сроки, сохранённое намерение отправки и проверки текущего владения предотвращают влияние устаревших запросов на последующие поколения. Повторный запуск user manager и переподключение шины отслеживаются без интерпретации как выхода. См. [внутреннее устройство жизненного цикла](reference/session-lifecycle.md) для точных гарантий, ограничений и восстановления.
:::

## Вывод CLI {#cli-output}

Оформленные отчёты используют виджеты Ratatui в памяти и выводят строки в обычную прокрутку. Определение терминала выбирает простой вывод при перенаправлении, `NO_COLOR`, dumb-терминале или малой ширине. Оформленное чтение журнала постепенно декодирует записи; простой вывод делегируется journalctl.

См. [разработку](development.md) для команд сборки и тестирования и [безопасность](SECURITY.md) для границ доверия.
